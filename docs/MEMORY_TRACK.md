# Трек «Память и роутер»: ассоциативная память, типы реплик, проверка через сеть

Открыт 2026-10-20 по просьбе владельца («основа для ассоциативной памяти и роутер для режима исполнения модели, затем валидация через интернет»). Покрывает M6 (память SQLite, ручные «запомни/вспомни»), M10 (автоизвлечение фактов, эмбеддер) и U-002 (проверка через сеть) — всё, что можно сделать на стенде без Jetson. Прототип живёт в `research/memory/`, в сервис переезжает после замеров (исполнитель, по карточке).

## 1. Зачем и что уже известно

- Окно 8k держит один вечерний диалог (CTX-1: 60 реплик = 4.5–5.1k токенов у e4b), но при 4k у gemma4 e4b recall падал до 0.47 (D-016/T-018) — то есть «память» модели кончается вместе с окном. Между днями и режимами A↔B контекста нет вовсе: нужна память **вне** KV.
- Thinking (T-025, D-025) память не улучшает и стоит 6 с на ход. Дешёвый путь — подать нужный факт в промпт явно.
- Внутри окна тоже есть промахи «разбавления» (e2b recall 0.67 при 8k): явная справка из памяти может помочь и там.
- Роутер типа реплики (COGNITION_4B рычаг 5, E-3) нужен, чтобы память, инструменты и правила включались только там, где уместно: болтовня не должна платить токенами за справку из памяти.

## 2. Устройство прототипа (`research/memory/`)

**Запись** = один обмен: `turn`, реплика собеседника, ответ Костяна, текст для эмбеддинга «Собеседник: … / Костян: …», множество стемов (5-символьные префиксы без стоп-слов). Пишется после каждого хода. В сервисе: SQLite (`exchanges`), sqlite-vec для векторов, `ts` и `session_id`.

**Выборка** (`AssocMemory.retrieve`): гибрид — косинус эмбеддингов (ollama `/api/embed`, `embeddinggemma` 300M; альтернатива для русского `bge-m3`) + 0.5 × доля стемов запроса, найденных в записи. Режимы `embed` / `kw` / `hybrid` — абляция, чтобы понять, нужен ли эмбеддер вообще или хватает ключевых слов на CPU без модели. Top-k (3), исключая обмены, которые и так в окне (`--memory dropped`) или только предыдущий (`--memory all`).

**Подача**: справка приклеивается к реплике **только в запросе**, в истории остаётся сырая реплика — история не растёт, кэш префикса не ломается:
```
[Память: из этого разговора раньше]
- (ход 11) собеседник: «Запомни код от домофона…» — ты ответил: «…»
[Конец памяти]

Напомни код от домофона, курьер завтра утром.
```

**Роутер** (`router.py`): шесть типов — `chat`, `memory`, `calc`, `explain`, `world`, `command`. Вопрос роутера идёт последним user-сообщением поверх той же истории (префикс KV общий, вопрос в историю не попадает). Через ollama — генерация одного слова (суррогат, `num_predict 6`, temperature 0); через llama-server — `top_logprobs` первого токена, то есть распределение по типам (decide-проход P-018). Политика по типу (`POLICY`): память только на `memory`/`calc`/`command`, правило «не знаю» одной фразой — на `world`, длинный бюджет — на `explain`, «считай по шагам, числа цифрами» — на `calc` (до нормализатора чисел, рычаг 12). Истина для оценки — поле `route_expect` в `ctx_probe_dialog.jsonl` (список = любой из вариантов засчитывается).

## 3. Эксперимент MEM-1 (стенд, ollama, T-026)

Тот же CTX-1, два seed, e4b-it-qat (и e2b как модель, которой память нужнее). Сетка:

| прогон | что измеряет |
|---|---|
| `--router label` @8k | точность роутера на 60 размеченных ходах, латентность вопроса, доля нераспознанных |
| `--memory all` @8k | recall и персона при справке на каждом ходу (цена: символов справки, TTFT) |
| `--memory dropped` @2048 | память **за окном**: recall при 2k против базы @2k (у e4b база 2k есть в T-014/T-018) |
| `--memory all --router apply` @8k | память только по роутеру + правила по типам: recall, персона, L2-оговорка, math |
| `--mem-mode kw` @2048 | нужен ли эмбеддер: выборка по стемам против гибрида |

**Результат (T-026, 2026-10-20, D-026; сводка `research/eval/results/ctx_probe_t026_2026-10-20.md`).** Роутер e4b 0.93 (e2b 0.60 — не держит). Память за окном при 2k: база 0.07 / 0.13 → **0.93 / 0.80**, выборка 1.0 / 0.87 (по одним ключевым словам 0.87). Внутри окна (8k) память не добавляет, но роутер с политикой даёт math 3/3 ×2 и оговорку на гравиметр 2/2 при справке вдвое короче. Дефект v1: справка в реплике пользователя читается как вставка собеседника — персона −0.4; формат v2 («[Ты помнишь: …]» + правило в системном промпте, `calc` без памяти) — **T-027**: персона 3.6 → 3.9, обсуждение ушло, но скобка копируется в начало ответа (4/60, 1/60), `world`-правило на ошибках роутера даёт «не знаю» вместо реплики, память внутри окна путает → v3 (справка после реплики, k = 2, условный `world`, память только за окном) — T-028: копирований 0, @8k политика без памяти держит math 3/3 и L2 2/2 при персоне ≈ база; но **роутер зависит от окна** (выпавший факт → `world` → «Не знаю.», recall 0.53 в конфигурации brain) и скобки породили ремарки → **v4** («Ты помнишь: …» без скобок, k = 3, `world` с памятью, уточнённый вопрос роутера) — **T-029**. Обвязка: окно по токен-леджеру обязательно (ollama режет молча), эмбеддинг через ollama 150–200 мс — для сервиса in-process CPU.

Метрики, независимые от генерации: `mem_retrieval_recall` (попала ли посаженная реплика в top-k на пробе), `router_acc`, `router_errors` (матрица «истина → ответ»). Зависимые: recall / math / персона / L2 как в CTX-1. Гейты: роутер ≥ 0.9; `--memory dropped` @2k возвращает recall к уровню 8k (≥ 0.85) при персоне −0 ± 0.1; `router apply` не хуже `memory all` по recall при меньшей справке.

## 4. Что дальше (после MEM-1)

- **T-027** — подтвердить формат v2 (персона при памяти = база). Затем в brain (T-016): окно по токенам, память на `memory`/`command`, роутер одним словом на llama-server (позже `top_logprobs`).

- **Объект состояния** (P-007, Q-012): кроме сырых обменов — JSON фактов (кот = Бублик; ключи: куртка → рюкзак с ходом 25; встреча: завтра 11:30, Дима, с собакой), обновляемый моделью с валидацией схемы. Это и есть брифинг для смены режима A↔B (A-12) и память между днями (M6). Проверка — та же CTX-1: ключи «переложил» должны вытеснять «в куртке» (t50 A3u, `must_not`).
- **Команды** (`command`): «запомни X» → запись с весом; «напомни вечером» → запись с триггером времени; «отвечай стихами» → флаг стиля в состоянии. Сейчас только классифицируются.
- **Сервис**: `services/memory/` с манифестом (CPU-only, эмбеддер ≤ 300 МБ RSS), топики `memory:store` / `memory:query` или прямой вызов из brain; sqlite + sqlite-vec; это первый «чужой» tenant платформы (R2).

## 5. Проверка через сеть (U-002) — набросок, прорабатывается после MEM-1

Роутер даёт тип `world`. Политика: (1) офлайн — правило «не знаю / не уверен» одной фразой в образе (уже в POLICY); (2) агентский режим (сеть разрешена владельцем явно, со звуком dial-up по U-003) — brain отвечает «сейчас проверю», параллельно запрос в поисковый API (локальный SearXNG или DuckDuckGo HTML — без ключей; выбор — Q-NNN), top-3 сниппета → второй вызов модели «ответь по этим выдержкам, если они не отвечают — скажи, что не нашёл» → вторая реплика. Сниппеты пишутся в память как запись с источником. Что мерить: доля `world`-ходов, где проверка изменила ответ (на CTX-1 это t17 гравиметр и t24 Марс), латентность до второй реплики, ложные проверки на `chat`. Отдельный эксперимент NET-1 — после MEM-1, карточка позже.

Связано: COGNITION_4B (рычаги 1, 2, 5, 12; E-2, E-3), AMBIENT_MODE (фильтр инициативы = тот же decide-проход), P-007, P-014, P-018, Q-012, Q-034, U-002, U-003, D-016, D-025, ROADMAP M6/M10.
