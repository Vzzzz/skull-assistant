# Decision log

Формат: «пробовали → упёрлись → выбрали». Одна запись — одно решение. Это ядро порогов №2–3 и статей; писать сразу, не откладывать.

```
### D-NNN · <решение> · <дата>
Контекст: milestone, что делали
Пробовали: варианты
Упёрлись: конкретная причина отказа (с числом, если есть)
Выбрали: и почему
Следствия: что это меняет в бюджетах / манифестах / плане
Связано: P-NNN (публикация), MEMORY_BUDGET строка
```

### D-010 · Выделить платформу (R2) как самостоятельный результат с контрактом сервиса · 2026-09-24
Контекст: возобновление после M4; в цели проекта явно заявлена «платформа для запуска компактных ml-сервисов».
Пробовали: v1 — диспетчер как часть черепа, бюджеты в таблице, сервисы захардкожены.
Упёрлись: без формального контракта диспетчер M8 неизбежно пишется под конкретные пять сервисов, и «платформа» остаётся словом в README.
Выбрали: манифест сервиса (ROADMAP §2), диспетчер читает манифесты; M1–M4 получают манифесты ретроспективно; M6 — первый tenant, добавленный «по контракту».
Следствия: +4–6 ч на манифесты до M5/M6; M8 упрощается (декларативно), статья №2 получает главу.

### D-011 · Публикации входят в план только через проверяемое следствие · 2026-09-24
