# Skull Assistant — Roadmap

Голосовой ассистент с характером в корпусе анатомического черепа.
Платформа: **Jetson Orin Nano Super 8GB** (unified memory). Тестовый стенд: ноутбук RTX 3080 Laptop 8GB, WSL2.

Бюджет времени: ~20 ч/нед (2 ч в будни + выходные). Оценки в чистых часах; календарь — при стабильном темпе. Коэффициент запаса на весь план: ×1.3–1.5.

---

## Архитектура (зафиксированные решения)

| Компонент | Решение | Обоснование |
|---|---|---|
| Ядро | Диспетчер поверх systemd + Redis Streams (шина) + SQLite (память) | Не пишем свой process manager; freeze = kill процесса |
| Основная модель | Мультимодальная VLM 4B INT4 (кандидаты: Gemma 3 4B / Gemma 4 E2B / Qwen3.5 4B) | Одна модель = диалог + анализ сцены; выбор по замерам, не по обзорам |
| Рантайм VLM | llama.cpp / Ollama; slot save/restore для freeze/thaw | vLLM тяжёл для 8 ГБ single-user; штатная сериализация KV-состояния |
| Звуковой тракт | CPU-only always-on: openWakeWord + KWS быстрых команд + Silero VAD + whisper.cpp + Piper | Минимум CUDA-контекстов; кольцевой буфер ≥2 с |
| Визуальный тракт | YOLOv8n (TensorRT) как триггер + VLM по событию | Не гонять VLM 30 fps |
| Своп крупных моделей | Процессная изоляция, kill/start; болванка 2.5 ГБ на стенде | empty_cache() не возвращает память ОС; контекст CUDA умирает только с процессом |
| Режимы работы | **A**: VLM 4B + полный сенсорный стек · **B**: большая MoE (стриминг экспертов с NVMe) + CPU-голос · **C**: «трофей» — максимальная модель любой ценой | Инвариант всех режимов: KWS/wake word не выгружается никогда (канал выхода). Скорость в B/C непринципиальна: медленная веская речь — часть персоны; C — асинхронный «спросил и ушёл» |
| Переходы между режимами | Briefing-паттерн (короткое резюме, не дамп истории) + голосовая маскировка: реплика «дай подумаю» произносится резидентным Piper **до** freeze | Обмен между моделями — только текст (KV несовместим); реплика маскирует teardown + load + пре-филл, латентность становится частью характера |
| Кандидаты режимов B/C | B: Gemma 4 26B-A4B (мультимодальна, минимальное ядро) → Qwen3.6-35B-A3B · C: Qwen3-Next-80B-A3B → GPT-OSS-120B | Правило отбора: активных ≤ ~5B, резидентное ядро ≤ ~5 ГБ; tok/s ≈ NVMe bw / активные байты на токен; активных ≥ 10B — мертво |
| Целевые форматы | INT4 (Q4_K_M / AWQ) веса, INT8 KV-кэш, FP16 базовая точность | Orin = Ampere: без FP8/FP4 |
| Диалоговые паттерны | Полудуплекс, barge-in через KWS, стриминговая склейка TTS, smart-turn | Референсы: Wyoming protocol, Pipecat |
| Обучение персоны | QLoRA на Colab (личный трек, без рабочего железа) → мерж → INT4 → деплой | Датасет: сотни–тысячи курированных реплик |

## Фаза 0 — Стенд и харнесс (до приезда устройства)

**6–10 ч**, идёт параллельно M1.

- [ ] WSL2 Ubuntu 22.04, systemd, Redis, CUDA; каркас репозитория
- [ ] Аудиозахват нативным Windows-процессом → кадры в Redis (репетиция модульности тракта)
- [ ] Отключить CUDA sysmem fallback (NVIDIA CP → Prefer No Sysmem Fallback)
- [ ] Болванка 2.5 ГБ VRAM для эмуляции бюджета Jetson
- [ ] Оценочный набор: ~20 диалоговых промптов в образе, ~10 vision-кадров «комнаты», ~15 кейсов tool-calling (запрос → эталонный JSON), 1–2 длинных диалога (30–50 реплик)
- [ ] GBNF-грамматика вызова инструментов; черновой system-prompt персоны
- [ ] Протокол замеров: 3 точки на сервис (процесс без модели / модель загружена / после freeze), nvidia-smi на Windows-стороне; пики — torch.cuda.max_memory_allocated в healthcheck
- [ ] **С первого дня: decision-log + таблица бюджетов памяти**

## Milestones M1–M4: голосовое ядро

Итого **55–85 ч ≈ 3–4.5 недели**. Правило: каждый шаг — отдельный systemd-юнит + топики на шине. Никаких монолитов.

### M1 — Wake word как сервис (8–12 ч)
openWakeWord, кольцевой буфер ≥2 с, событие в Redis Streams.
**Done:** слово-триггер стабильно детектится, событие видно в шине, юнит переживает рестарт.

### M2 — STT (6–10 ч)
faster-whisper / whisper.cpp (CPU), Silero VAD, склейка сегментов после wake-события.
**Done:** произнесённая после триггера фраза появляется текстом в шине с приемлемой задержкой.

### M3 — VLM в контуре (8–12 ч)
Ollama/llama.cpp сервисом, персона-промпт, маршрутизация текст → ответ.
**Done:** текстовый диалог с персоной через шину; ответы в образе.

### M4 — Диалоговый режим (25–40 ч) ⚠ самый недооцениваемый этап
Полудуплекс (микрофон глушится на время TTS, кроме KWS), barge-in «стоп/тише» через KWS-модуль, turn-taking (VAD-пауза → далее smart-turn), стриминговая склейка «TTS начинает с первого предложения VLM».
Паттерны заимствуем: Wyoming-компоненты как сервисы, логика interruption — из Pipecat.
**Done:** связный голосовой диалог без самодиалога с динамиком; перебивание работает; латентность «конец фразы → начало ответа» субъективно живая.

➡ **После M4 — оптимальная точка деплоя на устройство.**

## M5 — Неделя-1 на устройстве (15–20 ч ≈ 1 неделя)

1. **Bring-up:** JetPack; `nvpmodel -m 0 && jetson_clocks` перед любым замером; пустой след системы через jtop/tegrastats.
2. **Замеры по кандидатам в изоляции** (Gemma 3 4B / Gemma 4 E2B / Qwen3.5 4B + вайлдкарды Ministral 3 3B, Cosmos Reason 2 2B): память INT4, tok/s C=1, TTFT, image-токенов/кадр, рост KV на 512/4k/8k с FP16- и INT8-KV, function-calling по 15 кейсам (с грамматикой и без), удержание персоны на длинном диалоге, качество зрения pass/fail. Протокол сопоставимости с jetson-ai-lab: W4A16, ISL/OSL 2048/128.
3. **Гейт со-резидентности:** кандидат + Whisper + Piper + YOLOv8n одновременно; перезамер headroom и tok/s. Между прогонами — kill CUDA-контекстов.
4. **Решение по матрице:** гейт «влезает со-резидентно с запасом под KV» → tok/s ≥ 8–10 и TTFT ≤ ~1.5 с → надёжность tool-calling → зрение → персона/лицензия как тайбрейкеры.
5. Проверить slot save/restore с мультимодальным кэшем (image-токены) на целевой версии llama.cpp. Fallback: история + re-prefill.

⚠ Замеры недели-1 — открытый стенд. Финалиста перемерить в закрытом корпусе на устойчивость под троттлингом (см. M7+).

## Milestones M6–M9

Итого **80–120 ч ≈ 1.5–2 мес календаря**. M6–M7 частично параллелятся между стендом (логика) и устройством (перезамеры). M8 (своп) делать блоками по выходным — не фрагментировать.

### M6 — Прототип памяти (6–10 ч)
SQLite + FTS5: `memories(id, ts, speaker, text, tags)`; ручные «запомни/вспомни»; нормализация русского стеммером (Snowball/pymorphy) на записи и поиске; top-k в контекст.
Границу держать жёстко: никакого автоизвлечения — это M10.
**Done:** «запомни, что…» сохраняется, находится по ключевым словам в последующих диалогах.

### M7 — YOLO-триггеры (стенд 8–12 ч + устройство 5–8 ч)
Логика триггеров, дебаунс (человек в кадре = одно событие), маршрут «событие → кадр → VLM → реплика». На устройстве: TensorRT-движок, реальный FPS, перезамер со-резидентности.
**Done:** появление человека/объекта вызывает уместную реплику; ложных срабатываний терпимо мало.

🏁 **Порог портфолио №2: демо + заполненная матрица замеров + decision-log.** (~2 мес)

### M8 — Диспетчер: стейт-машина режимов A/B/C (33–50 ч) ⚠ второй по тяжести этап
Диспетчер реализует не «своп-слот», а стейт-машину режимов с декларативными резидентными наборами и бюджетами на каждый режим. Инвариант: KWS/wake word живёт во всех состояниях.

Lifecycle API: load / freeze / thaw / healthcheck. Семантика по бэкендам:

| | VLM (llama.cpp) | PyTorch (диффузия и пр.) | YOLO (TensorRT) |
|---|---|---|---|
| freeze() | slot save → kill | сериализовать конфиг/очередь → kill | kill |
| thaw() | start → slot restore | start → восстановить очередь | start |

Переходы между режимами:
- **Briefing-паттерн**: резюме диалога + релевантные записи памяти + задача, жёсткий лимит длины (сотни токенов — пре-филл большой модели в стриминге дорог, чем крупнее модель, тем короче брифинг)
- **Голосовая маскировка**: реплика перехода («дай подумаю», «мне нужно сосредоточиться» — набор фраз в образе) произносится резидентным Piper **до** freeze; обратный переход — опциональная реплика возврата. Латентность перехода — часть характера, не мёртвая тишина
- Обмен между моделями — только текст через Redis/SQLite (KV-кэши несовместимы между моделями принципиально)

Admission control по статической таблице бюджетов (из замеров), контроль факта через jtop; входы диспетчера: память, температура/троттлинг, OOM-политика (ядро и шина неприкасаемы, своп-слот гибнет первым).
Порядок: сначала вторая LLM 7–8B как своп-житель (тот же стек), SDXL — вторым. На стенде — только с болванкой 2.5 ГБ.
**Done:** цикл «диалог → реплика перехода → freeze VLM → тяжёлая модель отработала → thaw → диалог продолжается с того же места» проходит многократно без деградации свободной памяти; thaw ≤ ~10 с.

### M8b — Режим B: большая MoE со стримингом экспертов (15–25 ч)
После M8, до или параллельно M9. Скорость ответа в этом режиме непринципиальна — цель «адекватно общаться с ~30–40B-моделью полностью офлайн», и это достойный результат сам по себе.

- Сборка llama.cpp с unified memory (GGML_CUDA_ENABLE_UNIFIED_MEMORY); page cache ядра = LFU-кэш горячих экспертов
- Кандидат №1: Gemma 4 26B-A4B (мультимодальна — визуальные обязанности в режиме B берёт на себя); №2: Qwen3.6-35B-A3B
- Резидентный набор режима B: ядро MoE (~2.5–3 ГБ) + CPU-голос (KWS + whisper tiny/base + Piper, ~0.7–1 ГБ, ноль CUDA-контекстов) + опционально YOLO (~1 ГБ, ценой кэша экспертов)
- Матрица замеров: tok/s × резидентный набор (голый MoE / +голос / +голос+YOLO), стоимость пре-филла брифинга, устойчивость под длительной нагрузкой (NVMe греется)
- **Третий участник bake-off — «B-lite»: резидентная плотная 8–9B Q4** (кандидат: Qwen3.5-9B, ~4.5–5 ГБ + KV, влезает в бюджет эвакуации целиком). По качеству ≈ эквивалент стриминговой 26B-A4B (√T×A), но из памяти, а не с диска: ожидаемо 6–10 tok/s, нормальный пре-филл, предсказуемая латентность, профиль dense (рассуждение, следование инструкциям, стабильный JSON) против профиля MoE (эрудиция, мультимодальность). Сравнение по одному набору задач: tok/s, TTFT, качество рассуждения, устойчивость JSON-дисциплины. Возможный исход: B-lite — основной «режим подумать», стриминг MoE — для мультимодальных задач и как трамплин к режиму C (куда dense физически не заходит: стриминг плотных весов ≈ 0.2–0.4 tok/s, мертво)
- **Гейт по темпу**: ≥3–4 tok/s → диалоговый режим B со стриминговой склейкой TTS (медленная веская речь ≈ темп человеческой — «режим глубокой задумчивости», фича персоны); <2–3 tok/s → асинхронный режим («спросил — займись делом — череп ответит»), тоже валидный UX
**Done:** голосовой диалог с большой моделью офлайн end-to-end; матрица заполнена (включая B-lite vs стриминг MoE — это и есть прикладной ответ на вопрос «как использовать LLM крупнее резидентного класса на edge»); режим интегрирован в стейт-машину диспетчера с репликами перехода.

### M9 — Оптимизация основной VLM (20–27 ч внимания; параллельный трек с ~M3)
- Датасет персоны: синтетика черновиком + ручное курирование (10–15 ч ручного труда — не сжимается) + доля обычных инструктивных примеров против переобучения «в одну ноту»
- QLoRA на Colab (чекпойнты на Drive) или RTX 3080 laptop; при наличии — поверх официального int4-QAT чекпойнта
- Мерж → INT4 → прогон через харнесс: A/B против промптовой версии, дрейф персоны на длинном диалоге, ущерб tool-calling (JSON-дисциплина)
- KV INT8, подбор бюджета контекста; опционально спекулятивное декодирование с draft-моделью
**Done:** дообученная INT4-модель на устройстве держит персону ≥ промптовой на 40+ репликах, не хуже по tool-calling, короче system-prompt.

🏁 **Порог портфолио №3: стейт-машина трёх режимов с измеренными бюджетами + воспроизводимый рецепт персоны.** (~4–5 мес с учётом M8b; худший разумный сценарий ~6.5 мес). Три режима с матрицами замеров — системная глава, которой нет ни в одной из соседних публикаций.

### M10 — Расширение памяти (12–20 ч, риск расползания)
Автоизвлечение фактов силами VLM, sqlite-vec + лёгкий CPU-эмбеддер (multilingual-MiniLM), политика попадания в контекст.
**Done:** факты запоминаются без явной команды; выдача уместна, без мусора в контексте.

## Закупка железа (сверх Dev Kit)

- **NVMe ≥ 512 ГБ, TLC с DRAM-кэшем** — стриминг экспертов это длительное случайное чтение, DRAM-less диски на нём проседают. Прикидка по месту: 4B ~3 ГБ + 26B ~15 + 35B ~20 + 80B ~45 + 120B ~65 + датасеты/система — 256 ГБ уже тесно.
- **Радиатор на NVMe** — в закрытом корпусе под режимами B/C диск греется всерьёз.
- Микрофонный массив (ReSpeaker 4-mic класс), CSI-камера, динамик, охлаждение SoC (штатный вентилятор шумный — кандидат на замену), DP→HDMI переходник для отладки.

## Риски

1. **Интеграционная отладка на стыках** (аудио в WSL2, права устройств, гонки на шине) — главный пожиратель, источник коэффициента ×1.3–1.5.
2. **Мультимодальный slot restore** в llama.cpp — проверить в M5; fallback re-prefill готов.
3. **Термика в закрытом черепе** — троттлинг как ресурс диспетчера; вентиляция через затылок/foramen magnum; перезамер финалиста в корпусе. В режимах B/C второй источник тепла — NVMe под длительным случайным чтением.
4. **vLLM-only кандидаты** могут не пройти гейт со-резидентности — отсев в M5, не драма.
5. **Фрагментация M8 по 2 часа** — механику свопа делать выходными блоками.
6. **Граница личное/рабочее**: модели, данные, железо публичной части — только личные/открытые; рабочая 4090 не участвует нигде.

## Дисциплина

- Decision-log («пробовали → упёрлись → выбрали») — с первого коммита; это ядро порогов №2–3 и будущей статьи.
- Таблица бюджетов памяти обновляется при каждом добавлении сервиса; в бюджет пишется **пик**, не установившееся значение.
- Будни (2 ч): обвязка, скрипты, датасет. Выходные: интеграционные блоки (M4, M8).
