# Статья №1 — план глав (скелет, без текста)

Рабочее название (ROADMAP §4.2): **«Голосовой ассистент с характером на Jetson Orin Nano 8 ГБ: что реально влезает со-резидентно и как это проверить»**. Площадка — Хабр; версия для GitHub — английская выжимка. Пишется после порога №2 (D-027); сейчас — скелет: какие главы, какие числа куда, что уже есть, чего не хватает. Числа со стенда помечены *(стенд)*, их место займут числа с Orin (M5). Ось сравнения — MILO (P-021): то же железо, та же модельная семья, другие решения.

Правило для текста: каждая глава стоит на одном замере со ссылкой на сводку в `research/*/results/*.md` и на решение D-NNN; мнения без замера — только в «Что дальше». Тон — инженерный дневник, не реклама: отрицательные результаты в тексте, а не в сноске.

## 0. Лид (10 строк)

Что это: офлайн ассистент-череп, который видит, слышит, помнит и отвечает в своём тоне, на одном Orin Nano 8 ГБ; одновременно — платформа со-резидентных ML-сервисов с бюджетами по пикам. Три числа в лиде: память режима A (сейчас 6.3–6.5 ГБ из 7.6 *(стенд)* → Orin), персона по CTX-1 (4.1 из 5 у 4B против 1.9 у Qwen3.5-4B), ход диалога (0.3–1.8 с *(стенд)*). Фото платы в черепе (`docs/media/skull-jetson.jpg`). Одна фраза «как это делается»: два автора коммитов, журнал решений (README «Как это делается»).

## 1. Почему 8 ГБ — это не «запустить модель», а «уместить шесть»

Тезис: со-резидентность — главное ограничение, а не скорость. Голос (capture, wake word, STT, TTS), VLM с проектором, эмбеддер памяти, детектор — всё одновременно, и каждый CUDA-контекст стоит сотни МБ.
- Числа: `stack_2026-10-21.md` — голос 559 МБ (с voice id и пиком STT при распознавании 770–910, T-039), VLM 3038 + проектор 720 + кадр 46, эмбеддер 650 CUDA / 421 CPU, YOLO 160; итог 6.3–6.5 ГБ *(стенд → Orin)*.
- Правило «пики, три точки» (D-015): `ollama ps` занижает на 0.7–1.2 ГБ — `vlm_mem_stand_2026-10-12.md`.
- Правило «голос и эмбеддер — CPU-only»: CUDA-сборка эмбеддера даёт +176 МБ VRAM даже при `-ngl 0` (T-033).
- Контраст с соседями: MILO и Reachy кладут STT на GPU и живут с swap (P-021, P-022); Загускин на NPU 16 ГБ (P-024).
- Манифесты сервисов как контракт (T-007): бюджет, резидентность A/B/C, freeze/thaw — задел под главу про режимы (статья №2).

## 2. Выбор мозга: персона как метрика, а не tok/s

Тезис: для ассистента с характером выбирать модель по MMLU или скорости бессмысленно; нужен свой набор — CTX-1 (60 реплик, якоря памяти, счёт, «не выдумывай», персона по 13 репликам).
- 14 моделей 1.7–9B: `ctx_probe_candidates_2026-10-17.md`, `ctx_probe_summary_2026-10-13.md`; таблица «персона / recall / math / L2» (D-016…D-022). Gemma 4 E4B 4.1, E2B 3.3, Qwen3.5-4B 1.9, gemma3:4b выдумывает на L2.
- Глава «few-shot и размер модели» (D-021): примеры в промпте помогают E2B и мешают E4B — числа есть.
- Русский конец-в-конец: Spark-X2.6 (P-028) и MiniCPM-V 4.6 как отрицательные примеры (телеграф, латиница).
- Thinking не рычаг (D-025, `ctx_probe_t025_2026-10-19.md`): адаптивное размышление Gemma 4, ошибки счёта — это чтение чисел словами.
- Судья: абсолютная шкала 9B негодна, парный слепой 26B с перестановкой — 0.35 переворотов, согласие 7/9 (D-028, `judge_pairs_2026-10-23_*.md`). Честно: итоговую оценку персоны ставит человек/ядро по JSON.
- Методология — цитировать P-023 (качество по задаче, а не по MMLU), P-026 (что измерять у персоны).

## 3. Своя квантизация: −1.2 ГБ без потери персоны

Тезис: QAT Q4_K_M от Google — не предел; imatrix на русском калибровочном наборе и IQ4_XS дают 3.04 ГБ вместо 4.26 при персоне 3.95 против 4.1.
- `ctx_probe_kostyan-e4b-iq4xs-imx_2026-10-19.md`, `vlm_mem_qat_2026-10-19.md`, скрипт `research/quant/quant_e4b.sh` (D-023). «imatrix обязателен: −0.65 персоны без него».
- Рантайм: ollama против llama-server неразличимы по памяти, llama-server грузится быстрее и даёт slot save/restore и logprobs (D-024, `runtime_2026-10-19.md`); одной строкой — P-020 (SonicBoom: +20 % декода, но только x86).
- Заметка на будущее: LoRA + int4 ломается, int8 держит (P-034) — к статье №3.

## 4. Память за окном: 0.07 → 0.93 и почему формат справки — свойство модели

Тезис: при 2k контекста факты собеседника выпадают за 15 обменов; память по выпавшим обменам возвращает их, но как именно приклеить справку — вопрос к модели, а не к инженеру: шесть форматов, и модель обсуждает память вслух, пока формат не станет «её».
- `ctx_probe_t030_2026-10-23.md`, `ctx_probe_t026_2026-10-20.md`, MEMORY_TRACK §2–3; D-026. Таблица форматов v1…v6: recall / копии справки / ремарки.
- Роутер типов реплик как условие памяти (E-3, COGNITION_4B): шесть меток одним вызовом с общим KV-префиксом, 0.88–0.93; порог уверенности и `calc` только при числах (T-037). Пример «Как меня зовут?» после умножения → `calc` 0.42 → пересчёт — как иллюстрация, почему нужен порог.
- Через шину на боевом сервисе: recall 0.73–0.87 @2k, 1.0 @8k, ход 0.3–1.8 с (T-016/T-037).
- Цена KV-кэша на Gemma 4: cache reuse не работает с mmproj, при сдвиге окна полный префилл — на стенде ≤ 0.37 с, на Orin перемерить (P-033).
- Цитировать: P-025 (события как единица памяти — следующий шаг), P-005 (перенос KV между моделями не работает).

## 5. Инициатива и её цена: адресат по тексту не определяется

Тезис: главная UX-фича — фоновый режим («жёлтая уточка»: глаза в мониторе, руки в коде) — и главный технический узел. Отрицательный результат как результат.
- T-038 эт. 1: 70 реплик (обращения / бормотание / кот / телефон / гость / ТВ / подкаст / созвон / радио), 4B по тексту: precision 0.36 при recall 0.95 — узнаёт жанр, не адресата (`ctx_probe_ambient_*_2026-10-24.md`, D-029). Таблица ошибок по типам.
- Что добавляет информацию: чей голос (T-039: CAM++ на CPU, EER 0.018, +57 МБ, 23–66 мс; живьём 10/10 · 10/11 · 2/2; порог расщеплён owner / uncertain / other), сцена с камеры (YOLO: один / телефон у уха / двое / ТВ), взгляд как триггер, состояние разговора. [Числа этапа 2 — после T-003/T-038.]
- Режим уточки: «пора ли говорить» (respond / ack / listen, пауза как сигнал) — [этап 1б, числа будут].
- Соседи: у MILO и остальных нет ни триггера слушания, ни инициативы (P-021: старт с телефона, VAD 600 мс). Литература 2026: P-029 (пять действий контроллера ходов, «терпеливый → напористый»), P-030 (тот же каскад на Qwen3-4B с FSM-токенами, задержка 0.6 с), P-031 (конец хода как голова ASR).
- Следствие для железа: непрерывное слушание в полудуплексе = глухота на каждую реплику черепа → AEC (ReSpeaker Lite, D-013) раньше, чем планировалось.

## 6. Голос: что слышно и что это стоит

Тезис: CPU-only голосовой тракт укладывается в 0.6 с STT и RT 0.06 TTS; GPU-TTS красивее, но впритык по памяти.
- STT: 1.5 → 1.05 → 0.57 с (двойной вызов, `language="ru"`; I-01, T-001/T-037). Конец фразы по RMS — честно про VAD (I-03).
- Piper RT 0.055–0.09 (`piper_rt_2026-10-12.csv`); Qwen3-TTS 0.6B через qwentts.cpp: TTFA 0.02 с, RT 0.13, 1.9 ГБ VRAM на GPU, на CPU RT 1.1 — не реальное время (`qwentts_2026-10-21.md`, TTS_TRACK §7). Выбор владельца: голос `ryan`, FX — косметика.
- Фильтр речи (`core/speech.py`): Piper читает «звёздочка/доллар/бэкслэш таймз» — 0 из 780 ответов после фильтра.
- Стрим по предложениям и «первое аудио» — [T-003, числа будут; ориентир P-030 — 0.6 с end-to-end на том же классе каскада].
- Wake word: стоковый `hey_jarvis` ловит 9/10 отдельно, 3/4 слитно и теряет начало фразы на 0.27–0.57 с (`kws_monitor_2026-10-24.md`) — аргумент за триггер по речи и за своё слово на MCU (bitladder: FRR 2.1 % при FAR 1 % на DS-CNN 128×6, STM32F407).

## 7. Зрение на одной плате без ускорителя

Тезис: проектор зрения стоит 720 МБ, кадр 640×480 — 136 токенов и 0.5 с префилла, YOLO 11n на CPU — 160 МБ и 50 мс; зрение почти бесплатно, пока оно по событию, а не потоком.
- `stack_2026-10-21.md` (P3/P4), T-033; контраст: MILO вынес YOLO на Hailo, SmolVLM2 26–29 с на кадр (P-021).
- Визуальный триггер и взгляд как UI — [T-031, числа будут]; «капча кадра по запросу, а не поток» — взято у P-021/P-022.

## 8. Как это делается: два автора и журнал решений

Тезис: ИИ-ассистент в двух ролях (исследователь/исполнитель) по карточкам задач; человек — железо, прогоны, прослушивание, решения, приёмка. Что получилось у «режима двух агентов» за первые дни (T-001/T-002/T-016/T-037/T-038/T-039 за три дня), где он ошибался (ctx_bus с включённым TTS проговорил 500 ответов; `--cache-ram` по умолчанию → RSS 10.5 ГБ). Сравнение с MILO по видимости истории: у них релиз-сквош 6 коммитов одним днём, у нас — decision log с «пробовали → упёрлись → выбрали» (P-021 обсуждение). Без оценок, с фактами: сколько коммитов, сколько карточек, сколько отрицательных результатов записано.
