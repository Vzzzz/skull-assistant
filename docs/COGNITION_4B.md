# Когнитивный максимум из 4B: рычаги помимо долгой памяти и проверки через сеть

Открыт 2026-10-19 (вопрос владельца во время T-023). Отправная точка — что CTX-1 показал у 4B-класса (D-016, D-018, D-021): искажение фактов из контекста («встреча в 12:00» вместо 11:30), потеря побочных линий (Дима с собакой), арифметика без выкладки, уверенные выдумки на неизвестное, дрейф персоны на старте, многословие до переполнения окна. Долгая память (M6/M10) и проверка через поиск (U-002) закрывают часть; ниже — остальное.

## Уточнения (2026-10-19, вопросы владельца)

- **Thinking — не многократный проход по KV**: модель генерирует скрытые токены рассуждения обычной авторегрессией, они ложатся в KV как любые другие; цена — длина (декод + память KV), не повторное чтение. Многократный проход через слои — looped-архитектура (P-016, Nanbeige); «второй проход» (E-2) — ещё один запрос поверх тёплого KV. Три разных механизма с разной ценой.
- **Decide-проход (P-018) — общий механизм** для роутера (E-3), выбора инструмента (рычаг 2) и фильтра инициативы (AMBIENT_MODE): один forward той же 4B, распределение по вариантам; грамматика (рычаг 7) — после решения, для формата. Отдельная модель-классификатор не нужна.
- **Динамический few-shot — не дообучение**: веса не меняются, эталоны подбираются из банка на каждом ходу. «Обучение на устройстве» у нас только без весов: память фактов (M6), банк эталонов (может расти от одобренных владельцем реплик), офлайн LoRA на стенде (M9). QLoRA на Orin не планируется — не влезет и не нужно.
- **Режим B как консультант** — основной сценарий A↔B; латентность переключения маскируется звуком (U-003: щелчки HDD, dial-up при выходе в сеть) — бюджет «26 с» допустим, если сыгран.

## Эксперименты на стенде (тот же CTX-1, два seed, судья D-017)

- **E-1 Выборочное thinking.** `ctx_probe.py` получает `--think-on math,recall` (по `block`/`probe_for` диалога): на трёх задачах и шести пробах памяти — `think: true`, остальное — `false`. Метрики: math, recall, персона на обычных ходах (не должна просесть), латентность трудных ходов, `thinking_chars`. Гейт: math ≥ 2/3 у e4b-it-qat и e2b-it-qat при персоне −0 ± 0.1. **Сделано (T-025, 2026-10-19) — гейт не пройден, D-025**: флаг через ollama не принуждает (Gemma 4 думает адаптивно: 2–3 из 18 «трудных» ходов, 21–33 из 60 в `all`), math не растёт (ошибки — чтение словесных чисел, не арифметика), ход с размышлением 6 с (макс 20 с), диалог ×2.7, персона e4b −0.2; выигрыш только в оговорке на неизвестное (4/4) и recall e2b. Сводка `research/eval/results/ctx_probe_t025_2026-10-19.md`. «Когнитивный максимум без дообучения» в этом смысле = база + инструменты (рычаги 2, 12), не thinking.
- **E-2 Второй проход.** После ответа на пробу памяти — второй запрос в том же контексте: «Сверь свой ответ с тем, что собеседник говорил раньше. Если расходится — исправь одной фразой, если совпадает — повтори». Метрики: recall до/после, ложные «исправления», латентность. Гейт: recall +0.1 без роста персоны-штрафов.
- **E-3 Роутер.** Decide-проход по списку типов на каждом ходе (требует llama-server `n_probs` — T-024, либо генерация одного токена через ollama как суррогат): точность классификации на 60 ходах CTX-1 против ручной разметки; латентность. Гейт: ≥ 0.9 на четырёх типах. *2026-10-20: реализован в `research/memory/router.py` (6 типов, разметка `route_expect` в диалоге, `ctx_probe.py --router label|apply`), прогон — **T-026** вместе с памятью MEM-1 (`docs/MEMORY_TRACK.md`).*

Порядок: E-1 сделан (T-025, D-025) → E-3 (роутер, `n_probs` есть) → E-2 (второй проход — только для типов «факт/память» по роутеру); форсированное thinking на llama-server — Q-049, после T-016. Каждый — отдельная задача исполнителю; результат — D-NNN и строка здесь.
