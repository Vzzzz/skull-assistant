# Таблица бюджетов памяти

Правила (из v1): в бюджет пишется **пик**, не установившееся значение. Три точки на сервис: процесс без модели / модель загружена / после freeze. Обновляется при каждом добавлении сервиса. Стенд: nvidia-smi на Windows-стороне + torch.cuda.max_memory_allocated в healthcheck. Устройство: jtop/tegrastats, перед замером `nvpmodel -m 0 && jetson_clocks`, между прогонами — kill CUDA-контекстов.

Стендовые значения — предварительные (dGPU ≠ unified memory). Финальные — только с устройства, финалист — перемерен в закрытом корпусе.

## 2. Бюджеты режимов (устройство, 8 ГБ unified)

**Оценка режима A по стенду (T-033, 2026-10-21):** VLM IQ4_XS @8k 3038 + проектор 720 + голос 560–700 + YOLO CPU 160 + **эмбеддер 650 (замер 2026-10-23)** + **пик картинки 46** + система ~900 ≈ **6.1–6.3 ГБ** из 7.6 доступных → запас ~1.3 ГБ без swap; память на ключевых словах без модели (D-026: выборка 0.87 против 1.0) экономит 650 → 5.4–5.6. Владелец (2026-10-23): эмбеддер (и TTS) в одном процессе с VLM (multi-model llama-server) — один CUDA-контекст, цена — свап A/B чуть медленнее; проверить в T-016. **С Qwen3-TTS 0.6B на GPU** (T-013 шаг 1: 1.9 ГБ на dGPU, на Orin оценка 1.2–1.5 ГБ + второй CUDA-контекст) → **7.0–7.5 ГБ — впритык**; возможные компенсации: контекст 6k (−100), память на ключевых словах без эмбеддера (−~400), headless (−700).
