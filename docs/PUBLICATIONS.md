### P-036 · Recursive Flint (40B-A2.5B MoE для кода) и движок `rec` · 2026-10-25
Источник: github.com/recursive-oss/rec (Apache-2.0, 6 коммитов, 201 звезда); модель huggingface.co/RecursiveSI/flint (+ `flint-int4-gguf` 22.9 ГБ NVFP4 для CUDA, `flint-nvfp4-gguf`; сторонний Q4_K_M), релиз 2026-10-21  Тип: repo + release-notes
Тезис: `rec` — **не модель, а рантайм**: «custom inference engine for running Recursive's language models locally», только Apple Silicon (M4 Pro / M5 Pro / M5 Max, ≥ 48 ГБ unified, ~30 ГБ диска), Go, OpenAI/Anthropic-совместимый сервер на :11500, «1.4–2.6× пропускной способности llama.cpp» на M4 Pro (замер вендора, один конфиг, без префилла). Модель **Flint**: MoE 39.8B всего / ~2.5B активных, 49 слоёв, **256 экспертов, 6 на токен + общий**, контекст 256K (до 512K), Apache-2.0; позиционирование — **локальная модель для кодинг-агентов** (SWE-bench Verified 74.2 %, Terminal-Bench 2.1 54.9 % — цифры вендора); «125+ tok/s на MacBook Pro, ~24 ГБ памяти»; построена «в основном автоматизированной системой Eureka Machine». О русском и о диалоге — ни слова.
Привязка: A-08 / режим B (большая MoE со стримингом экспертов с NVMe, Q-045), P-001 (TurboFieldfare: 26B-A4B в ~2 ГБ RAM), P-003 (WARP), P-028 (Spark: «мозг инструментов» для блока (4)), D-027.
Проверяемое следствие: на стенде **нет** — 23–26 ГБ весов не помещаются ни в 8 ГБ VRAM, ни в 19 ГБ RAM WSL; `rec` на Linux не запускается вовсе. Теоретическая прикидка для Orin с NVMe: при 6 из 256 экспертов на слой × 49 слоёв и 4-бит весах на токен нужно ≈ 1 ГБ новых экспертов без попаданий в кэш → при 2–3 ГБ/с NVMe это **2–3 tok/s в лучшем случае** — тот же потолок, что у 26B-A4B (Q-045), только с меньшей активной частью и без известного русского.
Вердикт: **отклонить для режима A** (модель для кода, 40B, персона/русский не заявлены — класс Spark, P-028); **для режима B — отложить до Q-045**: мелкозернистая MoE (256 экспертов по ~0.15B) технически удобнее для стриминга, чем 26B-A4B, но смысл режима B у нас — «умнее поговорить», а не «написать PR»; кодинг-агент — не задача черепа. Движок `rec` — не для нас (только Apple).
Заметки: NVFP4-GGUF «для NVIDIA» — формат под Blackwell (RTX Spark, 150+ tok/s), на Ampere/Orin ускорения NVFP4 нет, нужен Q4_K_M от сторонних. Единственное, что стоит взять как ориентир: релиз 2026-10-21 показывает рынок локальных агентных моделей класса «2–4B активных / 30–40B всего» — именно этот класс и есть наш режим B, и к моменту Jetson выбор там будет шире, чем gemma4:26b-a4b.
Обсуждение: владелец (2026-10-25): «вот ещё репозиторий и модель» — ядро: интересна как сигнал по классу моделей для режима B, не как кандидат.

### P-035 · gpu-unlock (Zagitta) — удвоение темпа FP16/BF16 FMA на десктопных RTX 3000 до «профессионального» · 2026-10-25
Источник: github.com/Zagitta/gpu-unlock (5.3k звёзд, 23 коммита, модуль ядра Linux 1.0.0, GPL-2.0)  Тип: repo
Тезис: модуль ядра до привязки драйвера `nvidia` записывает селекторы скорости (техника CMP-анлока) и делает function-level reset PCI-устройства — у GeForce GA102/103/104/106 снимается искусственное ограничение темпа выдачи FP16/BF16 FMA с FP32-аккумуляцией. Числа пользователей: 3090 Ti GEMM 8192³ BF16 87.5 → 157.4 TFLOPS, TF32 42.6 → 82.6; по картам +25…80 % BF16; **префилл LLM +14…36 %, декод и INT8 без изменений**, выводы побитово те же. Немодифицированный драйвер; нужен параметр ядра `gpu_unlock.targets=`; после suspend переанлок ~1 с.
Привязка: A-02/A-08 (мозг и режим B), D-023 (своя квантизация — imatrix считается на стенде), T-020/T-021 (QLoRA на стенде), MEMORY_BUDGET §2 (стенд ≠ Orin).
Проверяемое следствие: **нет** — (1) стенд работает в **WSL2**: GPU там паравиртуализирован через dxgkrnl Windows-драйвера, Linux-модуль ядра не получает PCI-устройство и не может сделать FLR; (2) **Jetson Orin — GA10B**, интегрированный GPU без PCI-функции, драйвер nvgpu из L4T, в списке целей отсутствует; (3) 4090 (Ada) владельца в проекте не участвует и в списке целей тоже нет.
Вердикт: **отклонить** для проекта. Пометка на будущее: если на стенде появится голый Linux (не WSL) на десктопной Ampere — это бесплатные +25…80 % BF16 для QLoRA (T-021) и imatrix, но не для инференса IQ4_XS (декод упирается в память, INT8/INT4-ядра не трогает).
Заметки: ускорение только там, где считают в FP16/BF16 с FP32-аккумуляцией: обучение, префилл в f16. Наш прод-инференс — квантованные веса, flash-attention с KV q8_0 — выигрыш был бы в лучшем случае на префилле, а на Orin его нет вовсе.
Обсуждение: владелец (2026-10-25): «возможно, будет что-то интересное» — ядро: интересное есть, но для другой машины; на нашей связке WSL2 + Orin точек приложения нет.

### P-029 · LPS-TC: проактивные реплики через лёгкий контроллер ходов поверх любой речевой модели (2608.28630) · 2026-10-24
Источник: arXiv 2608.28630  Тип: paper
Тезис: контроллер (энкодер Whisper-large-v3 + адаптер + Qwen3-0.6B) слушает **оба** канала (пользователь и ассистент) и на каждом шаге 640 мс выбирает одно из пяти действий: ничего / обычная смена хода / **перебить** / бэкченнел («угу») / замолчать по barge-in; стиль задаётся текстом в двух измерениях — «терпеливый → напористый» (5 уровней) и частота/момент бэкченнелов. Делает полудуплексные модели (Qwen2.5-Omni) дуплексными, улучшает тайминг у Freeze-Omni: ITT F1 0.32 → 0.52; датасет WildTurn ≈ 2981 ч английских стерео-разговоров; задержка до первого ответа 1.4–1.8 с на A100.
Привязка: AMBIENT_MODE (фильтр инициативы), T-038, T-004 (barge-in), A-04.
Проверяемое следствие: нет — английский, Whisper-large + 0.6B рядом с VLM в 8 ГБ не влезает, веса/код не объявлены.
