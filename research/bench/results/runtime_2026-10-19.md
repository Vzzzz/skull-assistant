## 2. Slot save/restore (freeze/thaw для M8)

Контекст 4363 токена (24 КБ калибровочного текста), KV q8_0:

| Операция | Время | Примечание |
|---|---|---|
| save слота | **62 мс** | файл 71.5 МБ (≈16 КБ/токен при q8_0 → 8k ≈ 130 МБ) |
| остановка + перезапуск сервера | **3.3 с** | загрузка модели — доминирует |
| restore слота | **32 мс** | 4363 токена |
| продолжение диалога | prompt_n 5, cache_n 4354, 105 мс | кэш попал, пере-префилла нет |

**Freeze ≈ 0.1 с, thaw ≈ 3.5 с** для 4B на стенде (почти всё — загрузка весов). Это числа для манифеста brain: `freeze: slot-save-kill`, `thaw_budget_s: 4` (стенд). Своп через убийство процесса (A-06) стоит ровно время загрузки — KV не теряется.

## 3. logprobs (Q-034)

`/completion` с `n_probs` отдаёт распределение первого токена (`top_logprobs`) — паттерн «decide за один проход» реализуем на llama-server; на 361-токенном промпте — 272 мс префилла, 0.31 с на весь вызов. Первый токен ответа у Gemma — `'\n'`: для decide-промпта брать распределение после пропуска пробельных токенов или просить ответ без переноса. Детали распределения — `runtime_probs.log` (после правки парсера).
