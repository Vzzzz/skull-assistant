## Что сделано

**1. `core/manifests.py` + `deploy/modes.yaml`.**
- Валидация контракта ROADMAP §2:
  - обязательные поля;
  - `measured_on`;
  - `residency` — resident / evacuated;
  - глаголы lifecycle;
  - `never_evict` ровно у одного сервиса и резидентен во всех режимах;
  - на режим: сумма пиков резидентов + резерв KV ≤ бюджет.
- Бюджеты: стенд — VRAM и RAM раздельно; Orin — единый пул.
- Сервис может переопределить бюджет на режим (`modes.<M>.budget`).
- `python -m core.manifests` печатает таблицу, при нарушении — список и код 1. Проверено на сломанных копиях манифестов: нет `measured_on`, нет `never_evict`, перебор VRAM.

**2. Режим B у brain.**
- В манифесте `modes.B`; `llm_server.py` читает `mode:current` и пишет `mode:llm` — какую модель держит сервер.
- Резидентность brain в B: `evacuated` → `resident` (другая модель).
- Клиент `skull-brain` больше не тянет `skull-embed` через `Wants=`: в B эмбеддер эвакуирован, им владеет диспетчер.

**GGUF 26B-A4B.**
- Блоб `gemma4:26b-a4b-it-q4_K_M` в llama-server **не грузится**: `wrong number of tensors; expected 1014, got 658`, раскладка ollama — I-18.
- Основная модель `gemma4:26b-a4b-it-mtp-q4_K_M` (блоб `a8bdd07a…`, 17.1 ГБ) грузится — её и взял, как допускает карточка.
- Драфт MTP (блоб `7e78b02d…`, 1.2 ГБ) не подключал: первый токен упирается в префилл, не в генерацию.

**Размещение экспертов** (30 слоёв, эксперты 460 МиБ на слой; `-c 8192`, KV q8_0):

| Флаги | VRAM пик | Генерация | Префилл 3.4k | Первый ответ на 3.4k | Загрузка (тёплый кэш) |
|---|---|---|---|---|---|
| `--cpu-moe` | 3806 | 15.4 ток/с | 205 ток/с | 16.9 с | 5.4 с |
| **`-ncmoe 24` (принято)** | **6606** | **18.6** | **249** | **13.9 с** | 5.9 с |
| `-ncmoe 23` | 7060 | 19.4 | 255 | 13.5 с | 5.2 с |

- Взял 24: запас ~1 ГБ до бюджета B (7592).
- 23 — впритык (запас 532 МБ) ради +4 % генерации.
- RssAnon сервера ~0.5 ГБ, остальные ~16 ГБ `VmRSS` — mmap файла (кэш страниц).

**3. `core/dispatcher.py`, юнит `skull-dispatcher`** — по D-030.
- Redis: `mode:current`, `mode:transition` (TTL 300 с), `cmd:mode`, `events:mode` по фазам; `mode:slot:<режим>` — файл слота и хэш истории на момент сохранения.
- Переход:
  1. freeze эвакуируемых и сервисов со сменой модели, держатели GPU первыми;
  2. `mode:current`;
  3. thaw резидентов: health до бюджета, restore — только при совпадении хэша `dialog:history`.
- `never_evict` не трогается.
- Юниты установлены, но не `enabled` — не прод: `skull-vision` после T-031 и TTS на время замера. Диспетчер их не стартует и не гасит, пишет `not_managed`.
- При старте — reconcile: резиденты запущены, `skull-llm` держит модель режима, лишнее остановлено.
- **Откат проверен:** в манифесте подменил путь GGUF режима B на несуществующий.
  - Смерть `skull-llm` поймана через 1.3 с после старта — по состоянию юнита, без ожидания тайм-аута health.
  - Откат в A — 6.3 с, слот A восстановлен.
  - `--switch` вернул код ошибки.
- `systemctl --user` из юнита работает: в окружении нет `DBUS_SESSION_BUS_ADDRESS`, но есть `XDG_RUNTIME_DIR` — шина находится по нему. `systemd-run`/busctl не понадобились, в ISSUES не писал.

**4. Ручной переход.**
- `deploy/stand/skull-mode.sh A|B|status` (Git Bash → `wsl.exe`) и `python -m core.dispatcher --switch B|--status`.
- brain во время `mode:transition`:
  - на обращение (wake word или имя) — константа «Погоди, думаю.», без модели и без истории;
  - фоновая речь игнорируется;
  - взгляд не отвечает.
- Проверено: «Костян, ты тут?» посреди A→B → «Погоди, думаю.»; «так, где моя кружка» → проигнорировано.

## Серия 10 переходов (фразы `events:mode`, секунды)

После каждого перехода — один вопрос через шину («Сколько будет семь умножить на восемь?»). История от этого меняется, поэтому restore в серии каждый раз пропущен — путь полного префилла.

| Фаза | A→B, медиана [мин…макс] | B→A, медиана [мин…макс] |
|---|---|---|
| save слота | 0.02 [0.00…0.02] | 0.08 [0.06…0.08] |
| stop `skull-llm` | 0.40 [0.40…0.43] | 0.86 [0.81…1.25] |
| stop / start+health `skull-embed` | 0.06 | 1.22 [1.21…1.24] |
| start `skull-llm` | 0.04 | 0.04 |
| health `skull-llm` | **8.22 [7.01…32.81]** | **5.31 [4.86…6.16]** |
| переход всего | **8.74 [7.53…33.33]** | **7.46 [7.03…8.29]** |
| первый фрагмент ответа | 9.53 [8.33…11.15] (639–1240 ток) | 0.76 [0.63…0.95] (679–1363 ток) |
| **переход + первый фрагмент** | **18.1 [17.3…44.5]** | **8.4 [7.7…9.1]** |

- **Первый A→B (33 с)** — файл 26B был вытеснен из кэша страниц: 17 ГБ при 19 ГБ RAM WSL. Дальше — 7–9 с.
- **Health A после B — 4.9–6.4 с**, а не 3.5 с из T-024: 26B вытесняет из кэша файл e4b. `thaw_budget_s` brain поднят с 4 до 7 с.
- **Первый ответ в B 8–11 с при ~1k токенов**: brain делает два запроса — роутер и ответ, каждый с префиллом на 26B.

A→B→A без реплики между — история не менялась, слот A восстановлен за 11 мс.

| Где | Без restore (полный префилл) | После restore |

## CTX-1 через переход

- **Протокол:** реплики 1–30 в A → переход в B → 31–60 в B → переход в A → 5 контрольных вопросов на якоря первой половины.
- **Контрольные вопросы:** кот, встреча, ключи (после переноса в рюкзак), кинза, код домофона.
- **База:** то же без переходов, всё в A.

| | Через переход | База (всё в A) |
|---|---|---|
| recall по пробам диалога | **1.0** (15/15; пробы 34–58 — в B, по истории из A) | 1.0 (15/15) |
| recall дальних | 1.0 | 1.0 |
| math | 1.0 | 1.0 |
| обрезано / пустых | 0 / 0 | 0 / 0 |

## Замечания

1. **Холодный A→B — 44 с до ответа.** Файл 26B (17 ГБ) живёт в кэше страниц только пока его не вытеснили. На стенде это первый переход после долгой работы в A; на Orin кэша не будет вовсе (Q-045).
2. **Два запроса на реплику в B** — роутер и ответ; на 26B каждый префилл дорог. В B роутер можно делать дешевле или не делать — вопрос ядру.
3. **Восстановление слота в A срабатывает только при неизменной истории**, то есть почти никогда после разговора в B. Выигрыш при этом скромный: ~1.2 с на 5k токенов у e4b.
