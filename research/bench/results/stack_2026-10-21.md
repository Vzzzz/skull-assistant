# T-033 · Память полного набора режима A на стенде · 2026-10-21

Стенд (RTX 3080 Laptop 8 ГБ, WSL2, 19 ГБ RAM), `research/bench/bench_stack.sh`, CSV `stack_2026-10-21.csv`. Шаги накопительные: каждый следующий — поверх предыдущих. VRAM — `nvidia-smi` (весь GPU), RSS — `/proc/<pid>/status` (VmRSS; VmHWM — пик процесса). На стенде веса VLM лежат и в VRAM, и в RSS (mmap) — на Orin с unified memory они считаются один раз, поэтому «итог для Orin» ниже — оценка, не замер.

## Что это значит для Orin (оценка, 7.6 ГБ доступно по P-022)

| слагаемое | МБ | откуда |
|---|---|---|
| веса VLM IQ4_XS + KV 8k q8_0 + буферы | 3038 | P2 VRAM (на Orin — unified, один раз) |
| проектор зрения | 720 | P3 − P2 |
| пик запроса с картинкой | 46 | P3 2026-10-23 (136 токенов на кадр 640×480) |
| голосовой стек (CPU) | 560–700 | P1 |
| детектор YOLO 11n (CPU) | 160 | P5; на Orin CPU ~3–4× медленнее → 2–3 fps или на GPU (+CUDA-контекст) |
| эмбеддер 300M (CPU) | 650 | P4 2026-10-23; 0, если память на ключевых словах (D-026); без отдельного CUDA-контекста — только CPU-сборка или в одном процессе с VLM (multi-model llama-server, проверить в T-016) |
| система, Redis, Python | ~900 | P0 RAM used 463 + надбавки; у NVIDIA на Orin headless −700 МБ |
| **сумма** | **≈ 6.1–6.3** (с эмбеддером-моделью) / **≈ 5.4–5.6** (память на ключевых словах) | запас 1.3–2.2 ГБ до 7.6 — режим A влезает без swap; с Qwen3-TTS на GPU (+1.2–1.5 оценка) — впритык (см. `research/tts/results/qwentts_2026-10-21.md`) |

Сравнение с соседями (P-022): стек NVIDIA на Orin (Cosmos-Reason2-2B 2.2 ГБ + STT/TTS на CUDA) оставлял 223 МБ и жил на swap; у нас при модели вдвое больше остаётся ~1.5 ГБ за счёт CPU-голоса и одного CUDA-контекста. Проверка — M5.
