# CTX-1: достаточность контекстного окна для персоны, диалога и памяти силами одной VLM

Вопрос: какой `num_ctx` нужен, чтобы VLM **без нашей внешней памяти и без объекта состояния** держала персону, нить диалога и факты на протяжении бытового разговора? Ответ — базовая линия для M6 и для эксперимента с объектом состояния (P-007): всё, что внешняя память добавит сверх этой линии, и есть её ценность.

## Дизайн

Один и тот же **скриптованный диалог из ~60 реплик пользователя**, прогоняемый через ollama при `num_ctx ∈ {2048, 4096, 8192, 16384}` на каждой модели-кандидате. Системный промпт — `persona/system_prompt.md`. Температура 0.3, seed фиксирован, история передаётся целиком (как делает brain сейчас), без обрезки на нашей стороне — обрезает только ollama.

Пять блоков, перемешанных так, чтобы расстояние до «якорей» было известным:

| Блок | Реплик | Что проверяет | Что закладываем |
|---|---|---|---|
| 1. Бытовые фразы | 15 | тон персоны на коротких репликах | **6 якорей-фактов**: имя кота, время встречи завтра, где лежат ключи, что пользователь не любит, число (код от домофона), обещание («напомни про…») |
| 2. Длинная генерация | 3 запроса | удержание персоны на 400–600 токенах; галлюцинации | (а) «расскажи подробно, как устроен…» на реальную тему; (б) вопрос о **несуществующем** (вымышленный прибор/автор) — ждём отказ или оговорку, не выдумку; (в) «перескажи своё предыдущее длинное сообщение в трёх пунктах» — самосогласованность |
| 3. Математика | 3 задачи | следование правилу персоны «выкладка → итог в конце», точность | многошаговые задачи с проверяемым ответом (17×23, проценты, время в пути) |
| 4. Произвольные фразы | 10 | устойчивость к шуму и смене тем | обрывки, фраза по-английски, «забудь», противоречие ранее сказанному, просьба сменить тон |
| 5. Проверки памяти | 12 | recall на расстоянии | 6 вопросов на якоря из блока 1 (расстояние 10 / 25 / 45 реплик), «что ты рассказывал про…» (блок 2а), «какой ответ был у второй задачи» (блок 3), «о чём мы говорили в самом начале» |

Пробы памяти вставляются и в середину (после блока 2, после блока 3), и в конец — так видна кривая recall по расстоянию, а не одна точка.

## Метрики (автоматические, кроме персоны)

| Метрика | Как считаем |
|---|---|
| **recall@d** | доля якорей, верно названных на расстоянии d реплик (ключевые слова/число в ответе) |
| **math acc** | совпадение итогового числа; отдельно — соблюдение «итог в конце» |
| **hallucination** | блок 2б: выдумал ли (судья: да/нет); 2в: пересказ соответствует исходному (судья 1–5) |
| **persona score** | судья-модель с рубрикой 1–5 на 12 выбранных ответах: сухость/ирония, краткость, нет «отличный вопрос!», нет извинений, нет смайликов; 20 оценок перепроверить вручную |
| **ctx usage** | `prompt_eval_count` на каждом ходе: рост и **плато = момент обрезки ollama** (ранние реплики выпали) |
| **TTFT / tok/s** | по ходу диалога, рост с длиной контекста (тёплая модель) |

Судья — модель крупнее испытуемой. ~~На стенде `qwen3.5:9b`~~ — с D-017 (2026-10-15) локальный 9b только fallback (`judge_local`): систематические ошибки (пустой ответ → 5, английский → 1, плоские ответы → 5). Итоговая оценка — сильная модель другой семьи по сохранённым JSON (пока ядро в чате; API-опция — Q-033). Шкала: 0 = пустой ответ, 2 = обрыв на полуслове; L2 — fabricated / generic / hedged.

## Выход

Таблица `модель × num_ctx` → recall@45, math, hallucination, persona, ctx-плато, TTFT@60. Решение: **минимальный num_ctx**, при котором recall@45 ≥ 0.9 и persona ≥ 4 — это бюджет KV для режима A в манифесте brain. Если такого нет даже на 16k — это и есть аргумент за внешнюю память и объект состояния, с числами.

## Реализация (TASKS T-012)

`research/eval/ctx_probe.py`: читает `research/eval/ctx_probe_dialog.jsonl` (реплики с полями `block`, `anchor_id`, `probe_for`, `expect`), гонит диалог через ollama `/api/chat` при заданном `num_ctx`, сохраняет полный лог в `research/eval/results/ctx_probe_<model>_<ctx>.json`, считает автоматические метрики, формирует задания судье. Содержимое диалога — совместно: якоря и бытовые реплики пишет владелец (в его доме живут его кот и его ключи), структуру и пробы — ядро. Черновик диалога ядро готовит первым, владелец правит.

## Режим thinking (E-1, T-025)

По умолчанию `think: false` на всех ходах (думающие модели иначе тратят `num_predict` на размышление и отдают пустой `content`). `--think-on <блоки>` включает `think: true` на ходах с указанным `block` диалога (`everyday`, `probe`, `longgen`, `random`, `math`; псевдоним `recall` = `probe`; `all` = все), на этих ходах `num_predict` = `--think-predict` (2500). Текст размышления **не возвращается в историю** (как в `services/brain`), в JSON хранится усечённо (`thinking`, 1500 символов) для чтения. Метрики: `think_turns`, `thinking_chars_mean`, `think_ignored` (флаг запрошен, размышления нет — модель/ollama не поддерживает), `empty_on_think`, `wall_think_mean_s` / `wall_think_max_s` против `wall_plain_mean_s`, `wall_total_s`. Имена файлов получают суффикс `_think-<блоки>` (`_think-probe+math`, `_think-all`), базовые прогоны без thinking не перезаписываются. Сравнивать прогоны с thinking только с базой на том же промпте и seed; персона оценивается по тем же ходам `judge_persona` — при `all` они тоже думают, при `math,probe` нет (проверка, что thinking на трудных ходах не портит тон обычных).

Итог T-025 (D-025, `results/ctx_probe_t025_2026-10-19.md`): Gemma 4 через ollama думает **адаптивно** — флаг не принуждает (2–3 из 18 «трудных» ходов), так что `--think-on <подмножество>` измеряет не thinking, а ещё один seed; информативен только `all`. Сообщение «think requested, no reasoning produced» в логе — норма для Gemma 4. Метрика `thinking_chars_mean` — по реально думавшим ходам, `thought_turns` / `think_turns` — сколько из запрошенных.

Исправление метрики recall (2026-10-19): проба по задаче (t36, t55) засчитывалась только по цифре из собственного раннего ответа — словесный ответ считался промахом; теперь попадание = своя цифра **или** правильный ответ словами. `--judge-only` без `--judge` пересчитывает метрики из сохранённого лога (списки `expect` берутся из текущего диалога), оценки судьи сохраняются — так пересчитываются старые JSON (Q-050).

## Промпт персоны и утечка примеров (D-020)

Промпт берётся из `persona/system_prompt.md` при старте скрипта. Если в промпте есть few-shot примеры, **их реплики не должны совпадать с репликами диалога** — иначе модель воспроизводит пример дословно и ход не измеряет ничего (так было 2026-10-17 с v2: t05, t13, t59, M1). Версию промпта фиксировать в сводке; при сравнении версий — те же модели, тот же seed, второй seed для recall.

## Где лежат результаты и ручная валидация

- `results/ctx_probe_<model>_<ctx>.json` — полный лог прогона (реплики, ответы, токены, авто-метрики, оценки судьи). **Не в git** (`results/` игнорируется, кроме markdown).
- `results/ctx_probe_<model>_<дата>.md` — сводная таблица по окнам; `results/ctx_probe_summary_<дата>.md` — выводы.
- `results/ctx_probe_<model>_<ctx>_review.md` — **отчёт для ручной валидации**, строится командой `python3 research/eval/ctx_review.py results/<json>`: оценённые судьёй реплики с пустой колонкой «Моя оценка», все пробы памяти с автоматическим вердиктом, математика, галлюцинация и пересказ. В git; заполненный отчёт — основание для калибровки судьи и рубрики.
